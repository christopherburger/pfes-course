15: Objects and Classes

Introduction to Objects and Classes

Object-oriented programming is a paradigm that is focused on creating objects. Objects are entities that contain data and procedures. This data is known as attributes and the procedures are known as methods.

We have been using objects consistently throughout the entire semester as most everything in Python is fundamentally some kind of object.

The reasoning behind using objects is the idea of encapsulation, which is combining both data and code into a single entity. We can then leverage the benefit of data hiding, which is where the objet’s data attributes are hidden from code outside the object.

By restricting access to some components of the object we can protect from accidental corruption and have the benefit that outside code does not need to know anything about the object’s internal structure. This means we are free to change the code inside of the object as long as it still produces the same output.

Object oriented design also focuses on the idea of reusability, where the same object can then be used in different programs.

An Everyday Example of an Object

Consider the idea of a clock.

When it comes to defining the state of our clock its data attributes would be things like second, minute, hour, day, month, etc.

We need the ability to manipulate the object, and so we will need methods to do so. The question is, which methods should be accessible to outside code (public methods) and which should be exclusive to the object’s internal workings (private methods)?

Public methods would be common tasks that someone could expect to do to use the clock, like setting the time, setting the date, creating an alarm, etc.

Private methods would be things like how exactly the alarm functions to produce the sound at the correct time. This is not something one needs to know to use the clock, so it would be best off as a private method.

Classes

If we have an idea that we can represent as an object, we can specify a blueprint for it. This is a class, which is a collection of specific data attributes and methods for a particular type of object.

When using a class to create an object, we call the created version an instance of the class. The process of creating the object associated with a specific class is called instantiation. Since a class is designed to be a blueprint for an object that will be used repeatedly, then it is reasonable to expect that there can be many instances of one class at the same time. This is a true assumption, and Python differentiates different instances of a class by their memory location.

Class Definitions

To create a class, we need to define it. A class definition is a set of statements that define a class’s methods and data attributes.

Defining a class is similar to defining a function, we need the appropriate keyword class and the name of the class (by convention this starts with an uppercase letter).

To use initial parameters and define methods we need to use the self parameter. This is a special reference to the specific instance of the class.

class Clock:
    
    def __init__(self, seconds, minutes, hours):
        self.seconds = seconds
        self.minutes = minutes
        self.hours = hours

We can see a special initializer method, the constructor for the class. This takes in a single required parameter, self, and for our example, three other parameters passed in during instantiation of the class to the data attributes associated with our specific instance of the class Clock.

This initializer method is automatically executed when an instance of the class is created and is usually the very first method in a class definition.

Consider the following class designed to simulate a coin and the ability to toss it. Note that each method in the class has the self parameter.

import random

class Coin:

    def __init__(self):
        self.sideup = 'Heads'
    
    def toss(self):
        if random.randint(0, 1) == 0:
            self.sideup = 'Heads'
        else:
            self.sideup = 'Tails'
        
    def get_sideup(self):
        return self.sideup

To create a new instance of a class we use the format variable_name = ClassName().

my_coin = Coin()

To call any of the class methods using the created instance we use the dot notation like my_instance.method(). Because the self parameter references the specific instance of the object, the method will affect this instance.

print(my_coin.get_sideup())
Heads
my_coin.toss()
print(my_coin.get_sideup())
Tails

Note that we do not pass in self as an argument. It is implicit in the structure of the method definition. It needs to be there, but we do not need to concern ourselves with it when using the class.

Hiding Attributes and Methods

A key idea in object oriented programming is that certain components of an object data should be private.

In Python, this is indicated by placing two underscores (__) in front of an attribute name or a method definition.

This is our coin class redesigned to better indicate that the data attributes should not be accessed directly from outside the class.

import random

class Coin:

    def __init__(self):
        self.__sideup = 'Heads'
    
    def toss(self):
        if random.randint(0, 1) == 0:
            self.__sideup = 'Heads'
        else:
            self.__sideup = 'Tails'
        
    def get_sideup(self):
        return self.__sideup

Note that we did not apply the double underscores to the toss() and get_sideup() methods. That is because these are designed to be used outside of the class. That is, they are the expected way of interacting with the data attribute __sideup .

Accessor and Mutator Methods

Typically, all of a class’s data attributes are private and provide methods to access and change them. This is a safer way for code outside the class to retrieve or edit the value of attributes.

Accessor methods return a value from a class’s attribute without changing it. In our above example, the get_sideup() method is an accessor.

Mutator methods store or change the value of a data attribute. In our above example, the toss() method is a mutator.

Note that class methods can have multiple parameters in addition to self. This is common with mutator methods where we need to provide the new value of an attribute. We also saw this with the initalizer for our Clock class, it took in three different parameters apart from self.

Passing Objects as Arguments

Methods and functions often need to accept objects as arguments. When you pass an object as an argument, you are actually passing a reference to the object. The receiving method or function has access to the actual object Methods of the object can be called within the receiving function or method, and data attributes may be changed using mutator methods.

Identifying a Class’s Responsibilities

When it comes to creating a class, a good first step is thinking about what the responsibilities of the class are.

A classes responsibilities are:

  • The things the class is responsible for knowing which helps identify the class’s data attributes.

  • The actions the class is responsible for doing which helps identify the class’s methods.

To find out a class’s responsibilities look at the problem domain and deduce required information and actions.

Storing Classes in Modules

Classes can be stored in modules for future use using the import statement.

The rules for doing so are simple and similar to that of variable naming conventions. Additionally, the filename for the module must end in .py

Operator Overloading

Python has a powerful feature that allows a designer of a class to decide what an operation like == or < should mean. This is called operator overloading. With operator overloading, you can define what these operators do for objects of your own class.

For example, the == operator calls the special method __eq__() behind the scenes. You can override this method in your class to change the behavior of the == operator. This is useful for classes representing mathematical or data structures.

The __str__ method

The __str__ method is one of the most commonly overloaded methods. This method is automatically called when the object is passed as an argument to the print function or the str function.

my_coin = Coin()
print(my_coin)
<__main__.Coin object at 0x10e8081a0>

Note that the output of the print function for this instance of the Coin class is just a memory address. This may not be what we want for the default string representation of our coin.

Instead, we could use the value of the sideup attribute to see what the coin represents.

import random

class Coin:

    def __init__(self):
        self.__sideup = 'Heads'
    
    def toss(self):
        if random.randint(0, 1) == 0:
            self.__sideup = 'Heads'
        else:
            self.__sideup = 'Tails'
        
    def get_sideup(self):
        return self.__sideup

    def __str__(self):
        return self.get_sideup()

my_coin = Coin()
print(my_coin)
Heads

Object Oriented Programming

A Fraction Class

We can change the state of an object by making an assignment to one of its instance variables.

Consider the fraction class seen in 18.1 of our text.

class Fraction:

    def __init__(self, top, bottom):
        self.num = top # the numerator is on top
        self.den = bottom # the denominator is on the bottom
    
    def __str__(self):
        return str(self.num) + "/" + str(self.den)
    
    def getNum(self):
        return self.num
    
    def getDen(self):
        return self.den

The state of a fraction object can be completely described by representing two integers, the numerator and the denominator

myfraction = Fraction(3, 4)
print(myfraction)
3/4
print(myfraction.getNum())
3
print(myfraction.getDen())
4

Note that the __str__ method provides a “typical” looking fraction using a slash between the numerator and denominator.

Mutability

We can change the state of an object by making an assignment to one of its instance variables. For example, we could change the numerator of the fraction by assigning a new value to self.num. Likewise, we could do the same thing for self.den.

These methods are mutators because they mutate or change the internal state of our Fraction object.

Sameness

If two Fraction objects are the same, what does that actually mean?

  • Do they represent the same number?
  • Are they both the same object?

We can use the is operator to find out if two references refer to the same object.

myfraction = Fraction(3, 4)
yourfraction = Fraction(3, 4)

print(myfraction is yourfraction)
False
ourfraction = myfraction

print(myfraction is ourfraction)
True

Even though myfraction and yourfraction refer to the same rational number, they are not the same object. If we assign myfraction to ourfraction, then the two variables are aliases of the same object.

Shallow Equality

This type of equality is called shallow equality because it compares only the references (i.e., the memory locations), not the contents of the objects.

Using the == operator to check equality between two user defined objects will return the shallow equality result. In other words, the Fraction objects are equal (==) if they are the same object.

Deep Equality

We could define equality to mean the fractions are the same in that they represent the same rational number. This type of equality is known as deep equality since it compares the values “deep” in the object, not just the reference to the object.

If two variables refer to the same object, they have both shallow and deep equality.

Object-oriented Programming

Object-oriented programming involves four key ideas: encapsulation, information hiding, inheritance, and polymorphism. We have already discussed encapsulation and information hiding and will now cover inheritance and polymorphism.

Inheritance and polymorphism are mechanisms that help to enable code reuse and contract-based programming.

Inheritance

Recall the Point class from earlier in our textbook:

class Point:

    def __init__(self, initX, initY):
        self.x = initX
        self.y = initY
    
    def distanceFromOrigin(self):
        return ((self.x ** 2) + (self.y ** 2)) ** 0.5
    
    def __str__(self):
        return "x=" + str(self.x) + ", y=" + str(self.y)

Now, suppose we want to create a class that works like Point in every respect, but also keeps track of a short description for the point.

We could create a LabeledPoint class by copying and pasting the definition for Point, changing the name to LabeledPoint, and modifying the class to suit our purposes. However, any time you copy and paste code, keep in mind that you are copying and pasting bugs that may exist in the code. Inheritance provides a way to reuse the definition of Point without having to copy and paste.

This example defines a class named LabeledPoint that inherits from the Point class.

class LabeledPoint(Point):

    def __init__(self, initX, initY, label):
        self.x = initX
        self.y = initY
        self.label = label
    
    def __str__(self):
        return "x=" + str(self.x) + ", y=" + str(self.y) + " (" + self.label + ")"

Putting the name Point in parenthesis tells Python that the new class, LabeledPoint, begins with all of the methods defined in its parent, Point.

class LabeledPoint(Point):

We have also redefined two of the methods that LabeledPoint inherits from Point: __init__() and __str__(). This is called overriding. When a child class redefines methods that are defined in its parent, we say that the child overrides the functionality inherited from its parent.

Extending Classes

For the __init__ methods of Point and LabeledPoint, there is some duplication, the initialization of x and y.

We can eliminate the duplication by having LabeledPoint’s __init__() method invoke Point’s __init__() method. That way, each class will be responsible for initializing its own instance variables.

A method in a child class that overrides a method in the parent can invoke the overridden method using super().

In this example, line 4 invokes the __init__() method in Point, passing the values of initX and initY to be used in initializing the x and y instance variables.

class LabeledPoint(Point):

    def __init__(self, initX, initY, label):
        super().__init__(initX, initY)
        self.label = label

Composition

Inheritance is not the only way to reuse code. Composition occurs when an object stores a reference to one or more objects in one of its instance variables. The object is then able to reuse code in the objects it embeds within itself.

class LabeledPoint(Point):

    def __init__(self, initX, initY, label):
        self.point = Point(initX, initY) #The class Point is referenced in the LabelPoint class instance variable point
        self.label = label

Composition vs. Inheritance

We have seen two ways for a class to reuse code in another class. But hen do you use inheritance, and when is composition the better choice?

Composition, in general, is usually a better choice than inheritance to reuse code. Inheritance is appropriate when the proposed child class (the one reusing the functionality in its parent) represents a specialization of its parent. That is, class A is a specialization of class B if class A represents a specific type of class B. This is generally the case if you can fill in the following sentence with the names of the proposed child and parent classes: (child class) is a type of (parent class).
